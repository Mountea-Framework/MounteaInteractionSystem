Interactor Setup

The interactor lives on whatever should be able to interact - almost always your player Pawn, but also fine on an NPC or AI-controlled actor. It detects nearby interactables, picks one as focused (Tier 1), and lets you cycle/select its actions (Tier 2). Pick exactly one of the three component types below per actor.

Which interactor type?

ComponentDetection methodNeedsBest for
Interactor Component Overlap Physics overlap events on a sibling collision shape A collision primitive on the same actor (e.g. a Sphere Collision) First/third-person games - "walk into range"
Interactor Component Trace Periodic line or box trace from the owner Nothing extra - traces from the actor itself Camera-aim / crosshair interaction
Interactor Component Mouse Trace under the mouse cursor via the owning PlayerController Owner must be, or be possessed by, a Pawn with a PlayerController Top-down / strategy / point-and-click

Overlap - the one extra step

Add Interactor Component Overlap to your actor, then add a collision shape (e.g. Sphere Collision) as a sibling component - this is the volume that defines interaction range. On BeginPlay the component auto-discovers every primitive component on the owner and configures its collision responses for you (sets InteractionOverlap to Overlap, everything else to Ignore) - you do not need to touch collision presets by hand.

Only want specific components picked up instead of everything on the actor? Fill in Override Collision Components with the exact component names to use as the detection volume(s).

Safety trace - blocking detection through walls

Overlap volumes can poke into an adjacent room, so SafetyTracingSetup.SafetyTracingMode defaults to Location for Overlap interactors automatically - every candidate gets a secondary line trace validated before it's allowed into the focus list. Trace and Mouse interactors already trace to detect in the first place, so this defaults to None for them (turn it on if you still want an extra check).

ModeBehaviour
NoneNo secondary trace - whatever the primary detection found is trusted.
LocationTraces from a fixed StartLocation, or the owner's location if unset.
SocketTraces from a named socket (default "head") on the owner's mesh, falling back to owner location if the socket doesn't exist.

The trace channel resolves as: OverrideTraceChannelName (per-component, blank by default) → the project's InteractionTrace channel → hard fallback to Visibility if that channel somehow isn't registered. In practice this just works once collision channels auto-set-up on page 0.

Interactor Tag

Set Interactor Tag to identify this interactor (e.g. Mountea_Interaction.Interactor.Player or ...Interactor.NPC) - interactables can then whitelist/blacklist by this tag. See page 3 for the interactable side of this.

Wiring Enhanced Input

The plugin deliberately does not bind any input itself - it exposes plain interface calls and your project's own Input Component/Blueprint calls them, exactly like calling any other Blueprint function.

CallBind to
Execute_StartInteraction(Interactor, StartTime)Input Action Triggered or Started - key/button pressed
Execute_StopInteraction(Interactor, StopTime)Input Action Completed - key/button released
Execute_CycleAction(Interactor, Direction)An axis or two digital actions, Direction = +1 / -1
 
// Blueprint: Enhanced Input Action event → straight to the interactor component
IA_Interact (Started)   → Start Interaction  (Interactor, GetGameTimeInSeconds)
IA_Interact (Completed) → Stop Interaction   (Interactor, GetGameTimeInSeconds)
IA_CycleAction (Triggered, Axis1D Value) → Cycle Action (Interactor, Sign(Value))
