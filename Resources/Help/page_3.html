Interactable Setup

Add an interactable component to whatever should be interacted with — a door, an NPC, a lever, a pickup. All five types share the same base (weight, cooldown, lifecycle, tags) and differ only in how they complete.

Press and Automatic default bStandaloneInteraction = true — see below.

Standalone vs. action-cycling

bStandaloneInteraction decides whether this component forces itself as the always-selected action, or takes its place in a cyclable list.

SettingEffectUse for
trueThis component is always the highlighted action, index 0, no cycling UI needed.A single-purpose actor: a lever, a door, a pickup.
falseTakes its place among sibling interactable components on the same actor; the player cycles between them with Execute_CycleAction.An actor offering several interactions: an NPC with Talk / Trade / Inspect.
Multiple interactable components on one actor are automatically independent — no extra wiring needed to have e.g. Hold (enter as driver) and Mash (honk horn) coexist on the same car actor.

Multiple interactors (co-op)

Set MaxInteractors above 1 to let several interactors occupy the same interactable at once (e.g. two players lifting a heavy door together).

  • Hold / Automatic — one shared timer; whoever's join arrives while it's not already running starts it, everyone else just occupies a slot alongside them.
  • Mash — one shared press counter; presses from any occupant count toward the same threshold — genuine co-operative contribution.

Either way, when the interactable completes, every current occupant is released automatically — nobody is left silently locked on afterward, and the slot is immediately free for the next group.

Tag whitelist / blacklist

Gate who can join without disabling the interactable outright — compare against the joining interactor's single Interactor Tag (set on page 2).

FieldBehaviour when non-empty
RequiredInteractorTagsInteractor must match at least one of these tags (whitelist) — hierarchical "any" match.
ExcludedInteractorTagsInteractor must match none of these tags (blacklist), checked independently and in addition to the whitelist.

Example: an NPC vendor with RequiredInteractorTags = Mountea_Interaction.Interactor.Player never appears interactable to other NPCs; a Team A vehicle with ExcludedInteractorTags = Team.B rejects Team B players while staying open to everyone else. Both containers empty (the default) means no filtering at all.
