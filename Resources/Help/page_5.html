Testing & Troubleshooting

A minimal checklist to get one real interaction working in PIE, followed by the fixes for the snags that come up most often on a first setup.

End-to-end checklist

#StepPage
1Restart the editor once, so the auto-created collision channels are active.0
2Create the 4 config assets and assign them in Project Settings.1
3Add an Interactor Component (Overlap needs a sibling shape) to your player Pawn, set its Interactor Tag.2
4Bind Enhanced Input: Start/Stop/Cycle Interaction.2
5Add one Interactable Component (start with Press — simplest to verify) to a level actor.3
6Build a widget implementing Actor Interaction Widget, assign it to both UI configs.4
7Play. Walk up to the actor — attention widget, then interaction widget, then press your bound key.—

Common pitfalls

SymptomLikely causeFix
Nothing is ever detected Overlap interactor with no sibling collision shape on the actor Add a Sphere Collision (or similar) component alongside the interactor.
Traces/overlaps silently never hit Collision channels not yet active Restart the editor after the first load, or run Setup Interaction Channels from the Mountea Framework toolbar menu.
An interactor is rejected with no visible error RequiredInteractorTags / ExcludedInteractorTags mismatch Check the interactor's Interactor Tag against the interactable's tag containers; listen to OnInteractorRejected while debugging.
Player stays "stuck" after a Press/Automatic interaction These complete instantly on join, then immediately release — a widget/animation assuming a longer "held" window won't see one Use Hold instead if you need a sustained interaction window.
Second player can't join a shared interaction MaxInteractors is still 1 Raise MaxInteractors on the interactable (page 3) for co-op interactions.
Widget never appears, no errors Widget class doesn't implement Actor Interaction Widget Class Settings → Implemented Interfaces → add it, then re-implement the events.
Nothing seems configured at all One or more of the 4 config assets isn't assigned in Project Settings Not fatal — components silently fall back to hardcoded C++ defaults. Assign the assets (page 1) to actually control behaviour.

Where to look

All plugin logging goes through LogMounteaInteractionSystem — filter the Output Log for it. Verbosity (Info/Warning/Error, bitmask) is controlled by Log Verbosity in the same Project Settings page as the config assets.
